# PRD — 元素競技場（Genshin-like Web Game MVP）

版本：v0.1  |  日期：2026-08-23  |  狀態：M1 開發中

## 1. 願景與定位

以原神的戰鬥體驗為參考核心，用 **vibe coding（主要依賴 AI 輔助編程）+ 小團隊/個人** 的方式，
分階段打造一款可運行於 **手遊 + 網頁** 的日系寫實風 3D 動作 RPG。

> 誠實聲明：原神級開放世界不可能用 vibe coding 一步完成，本項目採取
> 「競技場 MVP → 垂直切片 → 完整產品」的分階段路線。

## 2. 核心設計決策（沿用既有對話結論）

| # | 項目 | 決策 |
|---|------|------|
| 1 | 戰鬥類型 | 即時動作制 ARPG（維持原神） |
| 2 | 隊伍 | 4 人切換（維持原神） |
| 3 | 元素反應 | 七元素反應系統（維持原神，MVP 先用 火/冰/雷 三元素） |
| 4 | 美術風格 | 日系寫實、7.5 頭身比例（非 Q 版 5 頭身），Low-Poly 起步 |
| 5 | 世界 | 開放世界（最終目標）；MVP 為單一封閉競技場 |
| 6 | AI 生成範圍 | 僅敵人外觀隨機（體型/顏色/配件/武器/光環） |
| 7 | 敵人基底 | 設計簡單：約 5 種基底 × 模組化配件 |
| 8 | 平台 | 網頁優先（WebGL），之後延伸至手遊 |
| 9 | 引擎 | **Unity 6 + URP + C#**（AI 生成生態最成熟） |
| 10 | 開發方式 | vibe coding，核心系統人類審查（數值/存檔/機率） |
| 11 | 商業模式 | F2P + 抽卡（MVP 不涉及） |

## 3. 里程碑規劃

| 里程碑 | 名稱 | 交付物 | 驗收標準 |
|--------|------|--------|----------|
| **M1** | 角色形象設計 | 主角設定稿、視覺參考圖、三視圖描述、身高/比例規格、配色表 | 用戶確認通過 |
| **M2** | 美術資產與場景 | 競技場場景設計、主角 3D 規格（或暫用模型）、5 種敵人基底設計 | 資產可導入 Unity |
| **M3** | 核心戰鬥原型 | 移動/普攻/元素戰技、3 元素反應、敵人 AI、4 人隊伍切換骨架 | 網頁可玩 demo |
| **M4** | MVP 整合 | 敵人隨機外觀生成器、UI/HUD、結算循環、WebGL 打包 | 完整一局可玩、可分享連結 |

## 4. M1 範圍定義（當前里程碑）

交付檔案位於 `docs/` 與 `assets/characters/hero/`：

1. `character-design.md` — 主角設定稿（背景、個性、元素、武器、服裝系統）
2. `design/proportion-sheet.md` — 7.5 頭身比例規格與三視圖文字規格（供後續建模/AI 生圖）
3. 視覺參考圖（AI 生成，存於 `assets/characters/hero/`）：
   - 主視覺立繪 / 三視圖 / 配色表色票圖
4. `prototypes/m1-character-viewer/` — 可在瀏覽器檢視的設計提案頁

## 5. 技術棧

- 引擎：Unity 6 LTS + URP + C#
- Web 預覽：WebGL（Unity 導出）；設計提案頁使用純 HTML/JS
- AI 生圖：Hermes Web UI 圖像生成 API（apikey-image-gen）
- 版本控管：Git

## 6. 風險與緩解

| 風險 | 緩解 |
|------|------|
| vibe coding 產出不可維護代碼 | _Core/ 目錄人類嚴格審查；AI 僅生成 Combat/Enemies/ 模組 |
| WebGL 性能瓶頸 | Low-Poly 起步；URP 移動端設定；敵人上限 4 隻同屏 |
| 子代理幻覺回報 | 所有子代理交付必附可驗證路徑，主流程逐一檢查實體檔案 |
| 美術成本失控 | AI 隨機外觀僅用「模型染色 + 配件組合」，不生成新模型 |

## 7. 驗收與流程約束

- **M1 完成後必須等待用戶確認**，確認通過後才進入 M2。
- 任何子代理回報的產出，主流程必須實際檢查檔案存在與內容，不接受口頭回報。
